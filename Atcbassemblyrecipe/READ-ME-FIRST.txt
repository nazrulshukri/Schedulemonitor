TWO PROBLEMS, TWO FIXES
=======================

1. THE BUILD ERROR - nothing to do with the code
------------------------------------------------
   JsonException: The input does not contain any JSON tokens
   ... GenerateStaticWebAssetsManifest.PersistManifest

A JSON file under obj\ is empty. It happens when a build is killed part
way through - which is exactly what happened when you had to taskkill the
locked DLL. MSBuild will not repair it, it just reads it again and fails.

Close Visual Studio, then in a command prompt in the project folder:

    rmdir /s /q bin
    rmdir /s /q obj

Reopen and build. Restoring packages takes a minute; after that it is
gone for good.


2. THE COLUMN RESIZE BUG - one file
-----------------------------------
Only wwwroot/js/excel-grid.js changed. Copy it over and hard-refresh the
browser (Ctrl+F5).

WHAT WAS WRONG
The tables are table-layout: fixed with a width of max(100%, Npx). Under
that rule, when the column widths add up to MORE than the table, the
browser does not overflow - it re-proportions EVERY column down to fit.
So dragging one column wider silently squeezed all the others. That is
how WSTYPE ended up a sliver showing just "S".

WHAT IT DOES NOW
- On the first drag, every column is pinned at the width it is currently
  showing, so none is left loose for the browser to squeeze.
- The table then grows to the sum of the column widths, and the panel
  scrolls sideways instead. Dragging a column now moves the ones to its
  right rather than shrinking them - the way a spreadsheet behaves.
- Double-click a resizer to let just that column size itself again,
  leaving the others where you put them.
- Reset column widths (in the account menu) puts the table back to the
  responsive layout.

Until you touch a resizer the table stays responsive exactly as before.

IF A GRID STILL LOOKS WRONG after the update, the old broken widths are
still saved in your browser: open the account menu and click Reset column
widths once.
