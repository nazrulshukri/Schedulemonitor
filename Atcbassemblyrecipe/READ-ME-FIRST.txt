SAVING IN AWACSWSTYPE NO LONGER JUMPS TO THE SAWING PAGE
========================================================
   Controllers/AwacsController.cs   (one file - needs a rebuild)


WHAT WAS WRONG
--------------
AwacsController.Create ended with:

    return RedirectToAction(nameof(TableSawing), new { promptAdd = true });

and the popup added "Please insert the required Table Sawing values".
That is why the URL you landed on was

    /Awacs/TableSawing?promptAdd=True

It dates from when AWACSWSTYPE only held SAWING machines, so adding one
and going straight to the Sawing grid to type its recipe was the intended
flow. The page holds WIREBOND machines now, which makes that jump both
unasked for and - for a wire bonder - the wrong grid entirely.


WHAT IT DOES NOW
----------------
Saving stays on AWACSWSTYPE with the new row visible, the same way Edit
and Delete on that page already behaved.

Failures stay there too. They used to render the standalone Awacs/Create
page, which was another jump away from the grid you were working in; a
validation error or a database error now comes back as a red popup on the
AWACSWSTYPE page itself.

The success popup tells you what happened next only when it is true:
adding a WIREBOND machine says it is already on the Wirebond page as an
empty row waiting for its recipe. It does not say that for SAWING,
because a new sawing machine does NOT appear on the Sawing grid by
itself - that grid is AWACSRECIPEBYWSTYPE, one row per recipe, not one
row per machine.

Saving a sawing RECIPE still returns to the Sawing grid, which is correct
and is untouched.
