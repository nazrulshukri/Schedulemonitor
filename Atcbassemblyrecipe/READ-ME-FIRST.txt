REGISTER THE WIRE BONDERS IN AWACSWSTYPE
========================================
AWACSWSTYPE is the workstation master: one row per machine, saying what
kind of machine it is (WSTYPE) and which table holds its recipes (WSDB).
It only ever carried SAWING / TBLSAWING. Wirebond recipes now live in
TBLWIREBOND, so the wire bonders belong in it too.

WHAT CHANGED IN THE APP
-----------------------
The AWACSWSTYPE page (Operations > AWACSWSTYPE) used to be locked to
SAWING in three places: the list query filtered WHERE wstype = 'SAWING',
the add row posted a hidden SAWING, and the validation rejected anything
that was not SAWING / TBLSAWING.

Now:
  * the list, the export and the row count cover SAWING and WIREBOND
  * the add row has a WSTYPE dropdown with both
  * WSDB is no longer typed in or posted at all. The server derives it
    from WSTYPE on every save - SAWING gets TBLSAWING, WIREBOND gets
    TBLWIREBOND - so the two can never disagree and nobody can point a
    sawing machine at the wirebond table.
  * the CSV import reads WSTYPE from the file and derives WSDB the same
    way, so a mixed file loads correctly

Other WSTYPEs in the table (TRIMFORM and so on) are deliberately still
out of this page. They have no recipe grid here.

HOW TO ADD THE MACHINES
-----------------------
Easiest, once the app is rebuilt:
   Operations > AWACSWSTYPE > Add Row
   type the WSID, pick WIREBOND in the WSTYPE list, save.
   WSDB is filled in for you.

For a batch, use Database/awacswstype-wirebond.sql. Block 1 shows what is
already in the table, block 3 loads a list of WSIDs in one statement and
skips any already registered, block 4 checks the result.

WHAT THIS DOES NOT DO
---------------------
Saving a wirebond RECIPE still does not touch AWACSWSTYPE, and should
not. Machines and recipes are separate records - editing a Sawing recipe
does not stamp AWACSWSTYPE either. This change puts the wire bonders in
the machine master; it does not tie the two tables together.

THE REST
--------
1. Copy the source files over your project, keeping the folder structure.
2. dotnet build, then dotnet run.
No database change is required for the code - only the machine rows you
choose to add.
