TABLE LAYOUT - TWO FILES, NO REBUILD NEEDED FOR THE CSS/JS THEMSELVES
=====================================================================
   wwwroot/js/excel-grid.js
   wwwroot/css/site.css

Copy both over, then HARD REFRESH the browser (Ctrl+F5). Both files are
static assets; if you are running from Visual Studio you may still want to
rebuild so the published copies update.


WHAT WAS WRONG
--------------
1. WHITE GAP ON THE RIGHT (your Sawing screenshot)
   The table was being set to exactly the sum of its column widths. When
   that total was narrower than the panel, the table simply stopped early
   and left a band of empty white beside it.

2. THE WHOLE PAGE SLID SIDEWAYS (your Wirebond screenshot)
   The Delete column AND the LOGOUT button were both cut off at the right
   edge - that is the page scrolling, not the grid.

   .app-shell is a grid whose content track is minmax(0, 1fr), so the
   track was fine. But .app-main is a grid ITEM, and a grid item's
   min-width defaults to auto - "at least as wide as my content". A table
   wider than the track stretched .app-main past it and took the whole
   page with it.


WHAT IT DOES NOW
----------------
The table is width 100% with a min-width of its column total:

  * columns narrower than the panel -> the table still fills the panel,
    no white gap, columns share the extra space
  * columns wider than the panel   -> the panel itself scrolls sideways,
    and the page does not move at all

.app-main gets min-width: 0, so overflow lands inside .excel-panel where
it belongs instead of pushing the layout.

Sawing, Marker, AWACSWSTYPE, AWACSLF and Wirebond all get this - it is the
shared grid script and the shared stylesheet.

If a grid still looks odd, your old saved widths are still in the browser:
account menu > Reset column widths, once.
