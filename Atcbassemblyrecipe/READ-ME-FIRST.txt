ORA-00904: "RECIPE": invalid identifier
=======================================
The page asks TBLWIREBOND for PACKAGE / PRODUCT / LEADFRAME12NC / RECIPE
and the table still has the old OCAP columns. Oracle names the first
column it cannot find, which is RECIPE. The database has to change.

RUN Database/tblwirebond-migrate.sql
------------------------------------
It converts the table in place with ALTER instead of dropping it, so the
grants, synonyms and privileges survive and it cannot fail because your
tablespace is named something other than OCAPSYS_DAT.

Open it, click anywhere in it, press F5.
   Toad for Oracle ... F5 = Execute as Script
   SQL Developer ..... F5 = Run Script

DO NOT use Execute Statement (F9 in Toad, Ctrl+Enter in SQL Developer) -
that is what produced ORA-00933 on the earlier version of this script.
The file is now ONE PL/SQL block ending at a / on its own line, so there
is nothing for the client to mis-split.

Safe to run twice. Every step checks the database first and skips itself
if it is already done, so a half-finished attempt is repaired by running
the whole thing again. If anything is still wrong at the end the block
raises an error naming exactly which column is missing.

Database/tblwirebond.sql is the DROP + CREATE alternative. Use it only
for a table that does not exist yet, or one you are happy to lose.

STEP 5 IS NOT OPTIONAL
----------------------
It is a separate problem from ORA-00904 and it hits the moment the grid
starts working. Edit writes to TBLRECIPEHISTORY and Delete writes to
TBLRECIPETRASH, both inside the same transaction as the save. Both tables
CHECK the table name against a fixed list that never included
TBLWIREBOND, so Edit and Delete fail with ORA-02290 and roll back - while
Add works fine, which is what makes it confusing.

THE REST
--------
1. Copy the source files over your project, keeping the folder structure.
2. DELETE these two - nothing references them any more:
      Views/WireBond/_WireBondFields.cshtml
      ViewModels/WireBondPanelModel.cs
3. dotnet build, then dotnet run.

Optional: block 3 of Database/tblwirebond-insert.sql copies the existing
WIREBOND rows out of AWACSRECIPEBYWSTYPE into TBLWIREBOND, so you do not
have to key them in again. It skips anything already there.
